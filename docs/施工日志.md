## 四、施工守则（agent 铁律）

1. **动代码前**：`git status` 必须干净；改 Rust 前跑 `cargo test --manifest-path src-tauri/Cargo.toml --lib` 确认基线 35+ 通过。
2. **改完必验**：`npm run check` + `cargo test --lib` 全绿才算完成；涉及 UI 的功能在 dev 模式手测。
3. **发布**：只走 `npm run release`（自动抬版本+三处同步+测试+打包+安装+验证），不要手动改版本号。发布会**结束运行中的画匣实例**。
4. **危险操作**：删除文件、改库数据、动真实库 `F:\Hthings\BENZI` 前，先说明影响并等管理员确认。
5. **库只进不出**：任何脚本不得把库内容发往外部；LINGSHI 联动导入后删除源压缩包**前必须确认画廊内已有完整副本**。
6. **Git 纪律**：每个逻辑单元一个 commit；不提交 `target/`、`node_modules`、`*.db`（.gitignore 已配好，别手贱 add）。
7. **编码坑备忘**：`.cmd` 纯 ASCII；VBS 要 UTF-16LE+BOM；PowerShell 写文件会带 BOM（用 Node 写 JSON）；Git Bash 双引号会吃 `\v` 等转义、`/c` 会被 MSYS 转换成 `//c`——写带反斜杠的内容一律用 Write 工具或脚本文件。
8. **备份纪律**：仓库已在 E 盘有双保险——`git push backup` 增量同步到裸仓库 `E:/GitRemotes/画匣.git`（远程名 `backup`），另有 2026-11-19 快照 `E:/画匣备份-20261119/`（git 全历史 bundle + 工作区副本，排除 target/node_modules）。每轮施工 commit 后顺手 `git push backup`。
9. **版本号即状态**：`package.json`/`Cargo.toml`/`tauri.conf.json` 三处由 release 脚本同步；看到不一致先跑一次 `cargo check` 让 lock 对齐再提交。**退出后自动发布打包的是工作区现状**——release.mjs 已加 dirty-worktree 警告（只警告不阻断），排发布前仍应确认工作区已提交。
