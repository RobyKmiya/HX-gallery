# 方案：浏览器内置阅读器 —— 工作台多标签（大改工程）

> 2026-11-24 · workbuddy 规划稿。目标形态：**一个窗口就是一张工作台**。
> 顶部标签条，主页 = 库主目录界面；每个标签可以是画廊 / 收藏夹 / 内建浏览器 /
> 导入界面等任意视图；浏览器成为其中一种标签类型，可多开。

## 一、为什么以前不能内置，现在可以了

浏览器是**两个原生子 webview**（工具栏 + 内容页），通过 `add_child` 挂在独立窗口上。
要把它们放进主窗（React 那层 webview），核心难题不是打开，而是**跟随**：

| 难题 | 1.1.24 之前 | 现在 |
| --- | --- | --- |
| 状态机 | `BROWSERS` 从未初始化，引擎全哑 | ✅ LazyLock 修好 |
| 尺寸/位置跟随 | `reposition` 持锁调主线程 API → **主线程死锁**（开网页即白屏卡死） | ✅ 1.1.24 铁律：持锁绝不碰 webview |
| 心跳可见性 | 卡死了都不知道 | ✅ 工具栏引擎心跳 + d2.log 面包屑/看门狗 |

即：**布局跟随与状态推送的基础设施已经立住**，内置只是把这些机制从「独立窗口」
搬到「主窗容器 + React 占位节点」。

## 二、总体架构

```
┌─ 主窗（main webview = React）──────────────────────────┐
│  TabStrip（React：主页/画廊/收藏/浏览器×N/导入 + ＋）     │
│  ┌─ TabContent（React 路由）────────────────────────┐  │
│  │  普通标签 → React 组件（画廊/收藏/导入…）           │  │
│  │  浏览器标签 → <BrowserHost>                        │  │
│  │    └─ 一个空 div 占位（React 只管量尺寸）           │  │
│  └────────────────────────────────────────────────┘  │
│  （原生层：工具栏 webview + 内容 webview 浮在占位处）    │
└──────────────────────────────────────────────────────┘
```

**关键认知**：原生子 webview 无法进 React DOM 树，只能「浮」在主窗上。
所以 React 侧只负责两件事：**量出占位矩形**、**告诉 Rust 显/隐与位置**；
Rust 侧维持现有 BROWSERS 引擎不动，新增「宿主 = main 窗」的挂载模式。

## 三、分期施工

### P0 · 探针（先证明路通，0.5 天）
- `browser.rs` 增加 `d2_embed(label, x, y, w, h)`：把工具栏+内容 webview
  `add_child` 到 **main 窗**（BROWSERS 引擎原样复用，只是宿主换了）；
- React 写一个最小 `BrowserHost`：`ResizeObserver` 量占位 div →
  `invoke("d2_embed_sync", rect)`（逻辑像素，Rust 乘 scale_factor）；
- 验证清单：窗口缩放/最大化/全屏时 1 帧内跟随；标签切换显隐；弹窗模态盖住
  浏览器；内容页能聚焦打字；老板键照常。

### P1 · 工作台标签壳（核心骨架，1~2 天）
- `TabStrip` 组件 + 全局 tab 注册表（zustand 或 App 级 state）：
  `{ id, kind: home|gallery|favorites|browser|import, title, icon, closable, payload }`；
- 首页标签不可关（主目录界面），其余可关；「＋」默认开主页；
- 视图路由按 `kind` 渲染；画廊/收藏/导入等现有视图原样搬进标签内容区；
- 每个标签的滚动位置/状态保存在注册表里（切换不丢）。

### P2 · 浏览器标签接入（1~2 天）
- **单引擎多标签**：浏览器标签不各自开引擎，而是共享一个 BrowserHost 实例；
  切到浏览器标签 → host 显示并 navigate/恢复该标签的 URL；切走 → host 隐藏
  （引擎状态保留，回来不重载）；
- 工具栏沿用现有 browser-toolbar 页（它已自带标签条、设置、心跳）；
  浏览器标签多开 = 工具栏内加内容标签，外壳只看到「一个浏览器标签」；
- **逃生舱**：工具栏加「弹出为窗口」按钮（一键把引擎搬回独立窗口），
  大屏多开场景保留旧路径。

### P3 · 键盘仲裁（0.5 天）
- 焦点在内容 webview → 浏览器快捷键（Ctrl+T/W…）；
- 焦点在 React 层 → 阅读器/全局快捷键（老板键走全局注册，不受焦点影响，
  1.1.25 已可自定义）；
- 冲突清单在设置面板里标注归属。

### P4 · 打磨（持续）
- 会话恢复：重启后按上次标签组合复原；
- 内存：隐藏超过 30 分钟的浏览器内容 webview 可卸载（回到时重载）；
- 广告拦截/油猴/下载入库等现有能力零改动。

## 四、最大的坑（P0 就要验证掉）

1. **模态盖不住原生层**：子 webview 是独立 HWND，永远浮在 React 之上 →
   打开设置/详情等模态时必须 `invoke` 隐藏浏览器 host，关掉再恢复；
2. **DPI**：React 量的是逻辑像素，`set_position/set_size` 要乘 scale_factor；
   1.1.24 的 reposition 已处理，搬进 main 窗时同样要过一遍；
3. **焦点抢夺**：点 React UI 后内容 webview 仍持焦点（打字进网页）→
   每次切换标签/打开模态时显式 `set_focus` 回主窗；
4. **引擎生命周期挂在 main 窗**：原来「关窗即退场」的逻辑要改成
   「最后一个浏览器标签关闭才退场」；
5. **resize 风暴**：拖拽窗口时 ResizeObserver 每帧触发 → Rust 侧节流
   （沿用 geometry 落盘的 900ms 去抖思路，但跟随要 <16ms，需用
   `run_on_main_thread` 直接 set，不做 IO）。

## 五、里程碑建议

| 期 | 交付 | 验收标准 |
| --- | --- | --- |
| P0 | 探针版（隐藏开关，不进主界面） | 缩放/最大化/切标签 1 帧跟随，模态盖得住 |
| P1 | 工作台标签壳 + 主页标签 | 主目录在标签里，开画廊/收藏各成一签 |
| P2 | 浏览器标签（单引擎 + 逃生舱） | 浏览器标签内正常浏览/油猴/下载入库 |
| P3/P4 | 键盘仲裁 + 会话恢复 | 全局键、应用键、网页键互不打架 |

每期独立发版可回退；P0 不过就停在独立窗口方案，不做半吊子内置。
