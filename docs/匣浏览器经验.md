# 匣浏览器 · 经验沉淀（匣系内置浏览器标准件）

> 2026-11-21 由画匣 D2 浏览器提炼，同日升级 **v2 多 webview 架构**。**往后所有匣系应用
> （画匣/影匣/音匣/未来的匣）的内置浏览器一律使用 `src-tauri/src/browser.rs` +
> `userscripts.rs` + `public/browser-toolbar.html`，不再各自造轮子。**
> 本文记录它的能力边界、设计决策与嵌入步骤——新匣开工前先读这份。

## 一、它是什么

| 层 | 内容 | 位置 |
| --- | --- | --- |
| 内核 | WebView2 = **Edge/Chromium**，网页兼容性与 Edge 天然齐平（这就是「chrome 核 / edge 核」的物理底座） | 系统自带，无需分发 |
| 引擎 | 窗口生命周期（存活探针/幽灵窗防护/销毁清理）+ 弹窗接管 + 下载上报 + 导航钩子 | `browser.rs`（`open()` 一个入口） |
| 外壳 | Shadow DOM 工具栏：地址栏/前进/后退/刷新/主页/缩放 ±/收起 | `browser.rs::TOOLBAR_SCRIPT_TEMPLATE` |
| 油猴 | `.user.js` 仓库 + `==UserScript==` 头解析 + @match/@include/@exclude 匹配 + GM_* 垫片 + 跨域 XHR 队列 | `userscripts.rs` |
| 管理 | 面板 UI：从网址/文件安装、启用停用、删除 | `D2Panel.tsx` 油猴区块 |

## 二、设计决策与理由

1. **为什么不做「装扩展」**：WebView2 没有扩展宿主，Chrome/Edge 扩展生态装不进来。
   落地「生态靠齐」的现实路径是**油猴内核**——Chrome/Edge 用户生态里最大的可编程层
   就是 Tampermonkey 脚本，`.user.js` 直接复用，兼容性收益最大、工程量最小。
2. **为什么一切交互都走「队列契约」**：浏览窗口加载的是外部站点，绝不能给它们
   invoke 宿主命令的能力（安全边界，`withGlobalTauri` 保持关闭）。三类交互全走
   「页面写队列 → Rust 轮询」：抓取解析 `window.__d2*`；油猴跨域 `window.__xkGmXhr`；
   工具栏 `window.__xkReq`（动作）→ `window.__xkState`（状态回写）。工具栏虽然是
   宿主自己的页面，也统一走队列——规则只有一条就不会出例外。
3. **为什么存活探针用回调**：卡退的渲染进程会留下「navigate 等调用返回 Ok 但页面
   永远不动」的僵尸窗（2026-11-21 实录：连发八条导航日志页面纹丝不动）。判断活着的
   唯一办法是发脚本探针并等回调真的回来（5 秒超时）。
4. **为什么脚本注入烘焙在窗口创建时**：Tauri 的 `initialization_script` 是建窗期
   注册的。改动油猴脚本后**重开浏览窗口**才生效（面板文案已提示）。未来可做
   「脚本变更后自动重建窗口」。
5. **幽灵窗防护**：建窗超时（30 秒）后线程里迟到的窗口直接 `destroy()`——否则
   WebView2 卡住恢复后用户会突然看到一扇无人管理的窗。
6. **v1→v2 的三个教训**（2026-11-21 实测）：① Shadow DOM 工具栏里
   `document.activeElement` 拿到的是宿主元素——「聚焦时不覆盖地址栏」的判定永远
   失败，地址栏每秒被打回原样，形同虚设；② 页内悬浮工具栏必然遮住站点自己的
   顶栏——占位必须是真空间；③ 无标签时弹窗只能 Deny 掉，登录类站点的弹窗流程
   直接断链。三条都只有多 webview 架构能根治。
7. **add_child 死锁**：tauri 明说 `Window::add_child` 在同步命令/事件回调里调用会
   死锁——一律「线程 + channel + 超时」包裹（`on_new_window` 回调里只入队，消化
   线程统一建标签）。

## 三、GM API 支持矩阵（V1）

| API | 状态 | 说明 |
| --- | --- | --- |
| GM_info | ✅ | 脚本名/版本/描述/uuid |
| GM_setValue / getValue / deleteValue / listValues | ✅ | localStorage 按脚本 id 命名空间；**跨站点不共享**（站点域隔离），单站脚本够用 |
| GM_addStyle / GM_addElement | ✅ | |
| GM_openInTab | ✅ | `window.open` → 引擎 `on_new_window` 接成新标签（不再顶掉当前页） |
| GM_setClipboard | ✅ | `navigator.clipboard`，失败退化 `execCommand("copy")` |
| GM_registerMenuCommand / GM_unregisterMenuCommand | ⚠️ | 空实现（没有油猴菜单 UI），只为不让脚本因 undefined 崩 |
| GM_getResourceText / GM_getResourceURL | ⚠️ | 空串（未做 `@resource` 仓库） |
| GM_notification | ⚠️ | console.info（未来接宿主 toast） |
| GM_download | ⚠️ | `<a download>` 触发，支持 `(url,name)` 与 `({url,name,onload,onerror})` 两种签名；跨域大文件建议直接用浏览器下载 |
| GM_xmlhttpRequest | ⚠️ | 跨域走 Rust curl 代劳；**只支持文本响应**——`responseType: blob/arraybuffer` 目前拿不到二进制（Comic Looms 的批量下载会踩这里） |
| @match/@include/@exclude | ✅ | 简化版通配：`*` → 任意段，`https?:` → http/https 两次尝试，`*://` → http/https，无协议头 @include 前缀匹配；**不实现** Chrome match-pattern 的 host 段特例（`*.example.com` 因 `*`→`.*` 实际可用） |
| @run-at | ✅ | document-start 立即；end/idle 都挂 DOMContentLoaded |
| @grant | ⚠️ | 解析但不区分，全部给全套 GM + 页面 window（unsafeWindow 同 window） |
| @noframes | ❌ | 暂未实现（iframe 也会注入） |

> **踩过的坑（2026-11-23，务必看）**：`@match *://*/*` 这类通配协议，Rust 侧
> `url_matches` 一直是对的，**JS 侧 loader 的 `urlMatches` 写错了偏移**
> （`"http" + pattern.slice(5)` → `"http?://..."`），导致 `*://*/*` 匹配不到任何
> URL。表现极具迷惑性：脚本装得好好的、GM 垫片也齐、控制台一条错都没有，
> 就是「没有任何按钮」——因为它一次都没被执行。Comic Looms 4.16.1 卡了整整
> 两天就卡在这里。教训：**油猴匹配逻辑有两份实现（Rust 编译期 + JS 运行时），
> 只测 Rust 等于没测**；改这块必须用真机/headless 加载真实脚本验证。
> 另外 loader 调脚本必须 `run.call(window, ...)`，否则 UMD 依赖（file-saver 这类
> `(function(global){...})(this)`）会把全局挂到 entry 对象上，脚本裸引用就崩。

## 四、嵌入指南（影匣/音匣接手步骤）

1. 把 `browser.rs`、`userscripts.rs` 复制进新匣的 `src-tauri/src/`，`lib.rs` 加
   `mod browser; mod userscripts;`（影匣/音匣与画匣同构，直接平移）。
2. 宿主调用：
   ```rust
   let (window, stop) = crate::browser::open(
       &app, url, format!("xk-browser-{uuid}"),
       crate::browser::BrowserOptions {
           title: "影匣 · 内建浏览器".into(),
           home: Url::parse("https://www.bing.com/").unwrap(),
           extra_init_scripts: vec![自有解析脚本],
           userscript_store: Some(store_dir),  // None = 关闭油猴
           size: (1180.0, 860.0),
           log: Some(Box::new(move |msg| 宿主日志(msg))),
       },
   )?;
   ```
3. 宿主在返回的 `window` 上注册自己的 `WindowEvent::Destroyed` 清理（清自己保存的
   句柄）；引擎已注册的清理（停止旗）独立运行，互不干扰。
4. 面板 UI 参考 `D2Panel.tsx` 的「油猴脚本」区块（安装/启停/删除三件套）。
5. 油猴仓库目录约定：`app_cache_dir()/browser/userscripts/`（`<uuid>.user.js` +
   `state.json`）。

## 五、已知边界与待办

- GM_xmlhttpRequest 仅文本响应（二进制/流式待续）；GM 值不跨站点共享。
- `@noframes` 未实现；`@grant` 不区分（不沙箱）。
- 无多标签页（单页 + 弹窗接管）；未来若要 tabs，加窗口内 Shadow DOM 标签条 +
  多 WebviewWindow 管理即可，引擎钩子已够用。
- 脚本改动需重开窗口生效（烘焙注入）；待办：脚本变更自动重建窗口。
- 桌面级 UA 切换（桌面/移动）未做；WebView2 `Settings.UserAgent` 可加。
- 「卡退」根因（站点脚本过重 vs 垫片冲突）仍未定论，恢复路径已闭合。
