# 匣浏览器 · 经验沉淀（匣系内置浏览器标准件）

> 2026-11-21 由画匣 D2 浏览器提炼，同日升级 **v2 多 webview 架构**。**往后所有匣系应用
> （画匣/影匣/音匣/未来的匣）的内置浏览器一律使用 `src-tauri/src/browser.rs` +
> `userscripts.rs` + `public/browser-toolbar.html`，不再各自造轮子。**
> 本文记录它的能力边界、设计决策与嵌入步骤——新匣开工前先读这份。

## 一、它是什么

| 层 | 内容 | 位置 |
| --- | --- | --- |
| 内核 | WebView2 = **Edge/Chromium**，网页兼容性与 Edge 天然齐平（这就是「chrome 核 / edge 核」的物理底座） | 系统自带，无需分发 |
| 引擎 | 窗口生命周期（存活探针/幽灵窗防护/销毁清理）+ 弹窗接管 + 下载上报 + 导航钩子 | `browser.rs`（`open()` 一个入口） |
| 外壳 | Shadow DOM 工具栏：地址栏/前进/后退/刷新/主页/缩放 ±/收起 | `browser.rs::TOOLBAR_SCRIPT_TEMPLATE` |
| 油猴 | `.user.js` 仓库 + `==UserScript==` 头解析 + @match/@include/@exclude 匹配 + GM_* 垫片 + 跨域 XHR 队列 | `userscripts.rs` |
| 管理 | 面板 UI：从网址/文件安装、启用停用、删除 | `D2Panel.tsx` 油猴区块 |

## 二、设计决策与理由

1. **为什么不做「装扩展」**：WebView2 没有扩展宿主，Chrome/Edge 扩展生态装不进来。
   落地「生态靠齐」的现实路径是**油猴内核**——Chrome/Edge 用户生态里最大的可编程层
   就是 Tampermonkey 脚本，`.user.js` 直接复用，兼容性收益最大、工程量最小。
2. **为什么一切交互都走「队列契约」**：浏览窗口加载的是外部站点，绝不能给它们
   invoke 宿主命令的能力（安全边界，`withGlobalTauri` 保持关闭）。三类交互全走
   「页面写队列 → Rust 轮询」：抓取解析 `window.__d2*`；油猴跨域 `window.__xkGmXhr`；
   工具栏 `window.__xkReq`（动作）→ `window.__xkState`（状态回写）。工具栏虽然是
   宿主自己的页面，也统一走队列——规则只有一条就不会出例外。
3. **为什么存活探针用回调**：卡退的渲染进程会留下「navigate 等调用返回 Ok 但页面
   永远不动」的僵尸窗（2026-11-21 实录：连发八条导航日志页面纹丝不动）。判断活着的
   唯一办法是发脚本探针并等回调真的回来（5 秒超时）。
4. **为什么脚本注入烘焙在窗口创建时**：Tauri 的 `initialization_script` 是建窗期
   注册的。改动油猴脚本后**重开浏览窗口**才生效（面板文案已提示）。未来可做
   「脚本变更后自动重建窗口」。
5. **幽灵窗防护**：建窗超时（30 秒）后线程里迟到的窗口直接 `destroy()`——否则
   WebView2 卡住恢复后用户会突然看到一扇无人管理的窗。
6. **v1→v2 的三个教训**（2026-11-21 实测）：① Shadow DOM 工具栏里
   `document.activeElement` 拿到的是宿主元素——「聚焦时不覆盖地址栏」的判定永远
   失败，地址栏每秒被打回原样，形同虚设；② 页内悬浮工具栏必然遮住站点自己的
   顶栏——占位必须是真空间；③ 无标签时弹窗只能 Deny 掉，登录类站点的弹窗流程
   直接断链。三条都只有多 webview 架构能根治。
7. **add_child 死锁**：tauri 明说 `Window::add_child` 在同步命令/事件回调里调用会
   死锁——一律「线程 + channel + 超时」包裹（`on_new_window` 回调里只入队，消化
   线程统一建标签）。

## 三、GM API 支持矩阵（V1）

| API | 状态 | 说明 |
| --- | --- | --- |
| GM_info | ✅ | 脚本名/版本/描述/uuid |
| GM_setValue / getValue / deleteValue / listValues | ✅ | localStorage 按脚本 id 命名空间；**跨站点不共享**（站点域隔离），单站脚本够用 |
| GM_addStyle / GM_addElement | ✅ | |
| GM_openInTab | ✅ | `window.open` → 引擎 `on_new_window` 接成新标签（不再顶掉当前页） |
| GM_setClipboard | ✅ | `navigator.clipboard`，失败退化 `execCommand("copy")` |
| GM_registerMenuCommand / GM_unregisterMenuCommand | ⚠️ | 空实现（没有油猴菜单 UI），只为不让脚本因 undefined 崩 |
| GM_getResourceText / GM_getResourceURL | ⚠️ | 空串（未做 `@resource` 仓库） |
| GM_notification | ⚠️ | console.info（未来接宿主 toast） |
| GM_download | ✅ | 支持 `(url,name)` 与 `({url,name,onload,onerror})` 两种签名；**先取字节再走 `blob:` 链接**（跨域 `<a download>` 会被忽略、直接把当前标签顶到图片地址），落到浏览器下载目录 |
| GM_xmlhttpRequest | ✅ | 跨域走 Rust curl 代劳；`responseType` 原样传给宿主，`blob`/`arraybuffer` 走 base64 二进制回传（解码后是真正的 Blob / ArrayBuffer，MIME 取自 `Content-Type`），`json` 自动 parse；跟随 302、默认带浏览器 UA、单文件上限 48MB；**同时最多 6 个在飞**，其余排队；**有真 `onprogress`**（每 150ms 报已收字节数，`total` 取 `Content-Length`）、`onloadstart`、`readyState` 1→4；失败时 `error` 一定是字符串（含 URL，脚本可正则提域名） |
| @match/@include/@exclude | ✅ | 简化版通配：`*` → 任意段，`https?:` → http/https 两次尝试，`*://` → http/https，无协议头 @include 前缀匹配；**不实现** Chrome match-pattern 的 host 段特例（`*.example.com` 因 `*`→`.*` 实际可用） |
| @run-at | ✅ | document-start 立即；end/idle 都挂 DOMContentLoaded |
| @grant | ⚠️ | 解析但不区分，全部给全套 GM + 页面 window（unsafeWindow 同 window） |
| @noframes | ❌ | 暂未实现（iframe 也会注入） |

> **踩过的坑（2026-11-23，务必看）**：`@match *://*/*` 这类通配协议，Rust 侧
> `url_matches` 一直是对的，**JS 侧 loader 的 `urlMatches` 写错了偏移**
> （`"http" + pattern.slice(5)` → `"http?://..."`），导致 `*://*/*` 匹配不到任何
> URL。表现极具迷惑性：脚本装得好好的、GM 垫片也齐、控制台一条错都没有，
> 就是「没有任何按钮」——因为它一次都没被执行。Comic Looms 4.16.1 卡了整整
> 两天就卡在这里。教训：**油猴匹配逻辑有两份实现（Rust 编译期 + JS 运行时），
> 只测 Rust 等于没测**；改这块必须用真机/headless 加载真实脚本验证。
> 另外 loader 调脚本必须 `run.call(window, ...)`，否则 UMD 依赖（file-saver 这类
> `(function(global){...})(this)`）会把全局挂到 entry 对象上，脚本裸引用就崩。

## 四、嵌入指南（影匣/音匣接手步骤）

1. 把 `browser.rs`、`userscripts.rs` 复制进新匣的 `src-tauri/src/`，`lib.rs` 加
   `mod browser; mod userscripts;`（影匣/音匣与画匣同构，直接平移）。
2. 宿主调用：
   ```rust
   let (window, stop) = crate::browser::open(
       &app, url, format!("xk-browser-{uuid}"),
       crate::browser::BrowserOptions {
           title: "影匣 · 内建浏览器".into(),
           home: Url::parse("https://www.bing.com/").unwrap(),
           extra_init_scripts: vec![自有解析脚本],
           userscript_store: Some(store_dir),  // None = 关闭油猴
           size: (1180.0, 860.0),
           adblock: true,
           log: Some(Arc::new(move |msg| 宿主日志(msg))),
       },
   )?;
   ```
3. 宿主在返回的 `window` 上注册自己的 `WindowEvent::Destroyed` 清理（清自己保存的
   句柄）；引擎已注册的清理（停止旗）独立运行，互不干扰。
4. 面板 UI 参考 `D2Panel.tsx` 的「油猴脚本」区块（安装/启停/删除三件套）。
5. 油猴仓库目录约定：`app_cache_dir()/browser/userscripts/`（`<uuid>.user.js` +
   `state.json`）。

## 五、工具栏契约与设置（2026-11-24）

**队列契约**：工具栏页/内容页都写 `window.__xkReqQ = []`（push 对象），引擎每
200ms 用一次 eval「取走并清空」整批执行。**不要用单槽 `window.__xkReq = {...}`**
——200ms 内连点两次，后一次会覆盖前一次，表现就是「按钮点了没反应」。

**状态推送**：引擎把 `{label, tabs, activeUrl, zoom, loading, settings}` 写进
`window.__xkState`（仅在变化时写）。工具栏只负责显示，缩放值/加载态/标签宽度
都以这里为准，别在页面里自己维护一份。

**动作表**（`action` 字段）：

| action | 参数 | 行为 |
|---|---|---|
| `nav` | `url` | 导航；不像网址则套搜索模板 |
| `back` / `forward` / `reload` / `stop` | — | 历史与加载 |
| `home` | — | 去设置里的主页 |
| `new` | `url` 可选 | 无 url 时按设置开主页/空白 |
| `close` / `switch` / `reorder` | `tabId`(+`index`) | 标签管理 |
| `nextTab` / `prevTab` | — | Ctrl+Tab 循环 |
| `zoomIn` / `zoomOut` / `zoomReset` | — | 按设置的步进 |
| `focusAddr` | — | 焦点交给工具栏地址栏 |
| `openSettings` | — | 打开 ⚙ 浮层 |
| `config` | `config` 对象 | 保存设置（写 settings.json + 立即生效） |

**⚙ 设置浮层**：工具栏只有 38px 高，弹层会被裁；做法是在同一浏览器窗口里临时
`add_child` 一条铺满窗口的 webview（`browser-settings.html`），页面自己画遮罩 +
居中卡片，创建在内容标签之后 → 天然在最上层。设置值走 `initialization_script`
注入（`add_child` 后立刻 eval 会打在 `about:blank`，页面一导航就丢）。

**设置落盘**：`%LOCALAPPDATA%\com.archivegallery.desktop\browser\settings.json`
（与 `adblock.txt` 同目录）。`settings.json` 不存在时，`opts.home` 作为主页
（宿主可传自己的主页）；一旦保存过，以文件为准。

**快捷键**：内容页注入 keydown 捕获（焦点在网页时工具栏收不到键盘），写成
`__xkReqQ`；`Ctrl+T/W/R/L`、`Ctrl+=/−/0`、`Ctrl+Tab`、`Alt+←/→`、`F5`。
开关在设置里，改完对已开标签立即 eval 生效；每次「加载完成」再同步一次
（新文档上下文稳定后才写，避免被导航重置）。

## 六、网页下载自动入库（2026-11-24）

网页里任何下载（`<a download>`、FileSaver 的 `saveAs`、blob 链接）都落到
`%LOCALAPPDATA%\com.archivegallery.desktop\cache\d2\downloads`，下载完成即调
`d2::import_downloaded_meta` 入库——**顺便把作品页的 tag 一起挂上**，不用再进
详情页手工补。

链路：

1. `on_download` 的 `Requested` 事件里，先读 WebView2 给的**建议文件名**
   （`destination.file_name()`，来自页面 `<a download="标题.zip">`），过一遍
   `d2::sanitize_file_name` 清掉 Windows 非法字符，只保留 `.zip/.cbz/.rar/.7z`。
   **不要**用 URL 末段推导：blob 下载的末段是随机 uuid、没有扩展名，入库那一步
   会被「不是 zip」直接拒掉（这是 1.1.18 之前「打包了但库里没有」的真因）。
2. 同一事件里起一个线程 `eval("window.__d2Meta()")`（≤3s），拿到
   `{title, tags:{命名空间: [标签…]}}`，按目标路径存进 `DOWNLOAD_META`。
3. `Finished`（success）→ 同一个线程里 `take_download_meta` 取元数据 →
   `import_downloaded_meta(app, path, title, tags)`：标签经 `d2::tag_drafts`
   变成 `ImportOptions.tags`（分类取站点命名空间，如 `female`/`artist`），
   另外固定挂一条 `来源/D2下载`。
4. 结果用 `__xkToast(msg, "ok"|"bad")` 弹在工具栏地址栏（唯一始终可见的窗格），
   同时写 `d2://download` 事件给 D2 面板。
5. 兜底：万一文件真的没有扩展名，`looks_like_zip()` 读文件头 `PK` 认 zip，
   按标题补 `.zip` 再入库，不白扔一个真压缩包。

## 七、已知边界与待办

- GM_xmlhttpRequest 的进度是「落盘字节数采样」（150ms 一次），不是真正的流式
  chunk；`abort()` 会 kill curl（≤800ms 生效），但已经下载的字节丢弃。
- GM 值用 localStorage，按站点域隔离，**不跨站点共享**。
- `@noframes` 未实现；`@grant` 不区分（不沙箱）。
- 脚本改动需重开窗口生效（烘焙注入）；待办：脚本变更自动重建窗口。
- 桌面级 UA 切换（桌面/移动）未做；WebView2 `Settings.UserAgent` 可加。
- 「卡退」根因（站点脚本过重 vs 垫片冲突）仍未定论，恢复路径已闭合。
- 设置浮层是「铺满窗口的 webview」，窗口缩放时靠 `reposition` 跟着改尺寸；
  若将来做真·多窗口，要改成独立窗口或原生模态。
- 下载入库的标签分类直接用站点命名空间（`female`/`artist`/`parody`…），
  不做中文映射；译名由库里的译名字典负责（`yuri → 百合` 这类）。
- 元数据只在**下载开始那一刻**抓一次；那时页面已跳走/已关掉，就退化成普通
  入库（无标签），不会阻断下载。

  失败时 `error` 必定是带 URL 的字符串——漫画织机的 `onerror` 会直接

- **2026-11-24 · V3.0**：工具栏全部按钮修好（单槽→数组队列、新建标签不再复制

  取消：页面置 `aborted` → 宿主探针 kill curl（≤800ms），按 TM 语义回调
  `onabort`+`onloadend`，不回半截数据。
- **2026-11-24 · V3.1（致命）**：**浏览器状态表从来没被初始化**。
  `static BROWSERS: Mutex<Option<HashMap<…>>> = Mutex::new(None)`，而全仓没有一处
  把它写成 `Some(..)` —— `register_browser` 的 insert 落在 `None` 上被静默丢弃。
  后果是一条真因解释了两个现象，且**一声不响**：
  - 工具栏轮询器第一轮 `browser_exists == false` 直接 return → 顶端按钮全哑、
    标签条空白（压根没有状态推送）；
  - GM 跨域轮询器同样退场 → 织机所有 `GM_xmlhttpRequest` 图片请求没人接，
    全部等到自己超时 → 满屏 `Error: timeout`、用户说的「时延爆表」；
  - 页面 webview 本身照常显示，从外面看像「按钮坏了」，其实是引擎死了。
  改 `LazyLock<Mutex<HashMap>>` 后不可能再忘记初始化；轮询器进出各留一行日志；
  工具栏加「引擎心跳」——3 秒没收到状态就在地址栏显示「引擎无响应 · 点这里重连」，
  让下次通道故障**看得见**而不是靠用户猜。
  **验证方法（可复现）**：给 WebView2 传 `--remote-debugging-port` 起一个隔离
  数据目录的实例，用 CDP 在主窗口 `invoke('open_library')`+`invoke('d2_open')`，
  再连工具栏 target 逐个 `element.click()` 校验 `__xkState` 变化：19/19 通过
  （状态推送、缩放三键、连点不丢、新建/切换/关闭标签、刷新/后退/前进/主页、
  设置面板、blob 下载）；另推一条 `__xkGmXhr` pending 验证 GM 通道真的回了 200。
- **2026-11-24 · V3.1（下载入库）**：网页下载改「保名 + 带标签 + 有回执」：保留
  WebView2 建议文件名（清非法字符），不再用 blob URL 的 uuid 当文件名；下载开始
