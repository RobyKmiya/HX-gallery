# 散图收藏夹 · 设计方案

> 2026-11-21 · zcode 起草。管理员需求原话：散图收藏夹，持续更新添加图片，多区收藏统一管理，
> 单图打分和收藏，无缝从画廊收藏图片下载并收藏到单图收藏夹，为节省空间可指向源文件位置，
> 和画廊收藏夹分开独立，各散图收藏夹以文件夹形式创立方便一键复制粘贴导入图片，
> 但收藏夹只记录名头不实际迁移图片。**本方案先查语义冲突、补齐缺口，管理员拍板后开工。**

## 一、需求重述（结构化）

| 需求点 | 拆解 |
| --- | --- |
| 散图收藏夹 | 与「画集」并列的第二种收藏对象：**单张图片** |
| 多区收藏，统一管理 | N 个散图区（各自独立），一个统一的管理/浏览入口 |
| 文件夹形式创立 | 每个区对应磁盘上一个真实文件夹 |
| 一键复制粘贴导入 | 管理员手动往文件夹里丢图 → 应用扫描登记 |
| 只记录名头不实际迁移 | 记录 = 路径/引用，画匣**不复制、不移动、不重命名**任何外部文件 |
| 单图打分 + 收藏 | 每张图独立评分（与画集同刻度 0–10）+ 收藏（红心）标记 |
| 从画廊无缝收集 | 阅读器/画廊里看到喜欢的页 → 一键收进散图区 |
| 可指向源文件位置（省空间） | 收集自画廊的页默认**指向源**（archive_id + page_index），不落盘；需要独立文件时显式「提取另存」 |

## 二、语义冲突与张力检查（管理员点名要查的）

### 冲突 1：「文件夹形式」×「不实际迁移」——不冲突，但要分清两种记录
文件夹只承载**手动放入的文件**（复制粘贴来的），记录指向它们；「从画廊收集」的页
有第二种记录形态：**源页引用**（压缩包还在原地，零拷贝零空间）。两种形态在同一个区里
混存，每条记录带 `kind`（file / archive_page）。**结论：不冲突，但必须在 UI 上让两种
记录可辨识**（archive_page 型给个小角标「源自：《包名》P37」）。

### 张力 2：「从画廊下载」×「不迁移」——真正的拍板点
从压缩包里「下载」一张图，物理上只有两种结果：落一个文件（占空间）或不落盘（指向
源页）。**默认建议：指向源页**（省空间、零等待、阅读协议现成）；菜单里保留
「提取到文件夹」显式动作给想要独立文件的场景。风险：源包被移出库/删除后指向型记录
失效——失效记录标记「源缺失」（与画集 missing 同款处理），不静默消失。

### 冲突 3：「文件夹形式」×「指向源文件位置」——文件夹之外还能不能收？
能。指向型记录天然支持任意路径（比如收藏桌面上的一张图而不搬动它）。V1 先收两处：
① 绑定文件夹里的文件；② 画廊源页。「扫描任意文件夹」待办。

### 补充 4：管理员没说但必须定的（均已给默认值，可否决）
| 点 | 默认方案 |
| --- | --- |
| 区的文件夹建在哪 | 默认根 `F:\Hthings\散图\<区名>\`（与 BENZI 同盘）；也允许「绑定已有文件夹」指向任意位置 |
| 同一路径收进多个区 | **允许**（引用语义）；同区内按路径/源页去重 |
| 文件被外部移动/删除 | 扫描时标「缺失」，不静默删记录；恢复文件自动复活 |
| 删除记录 | 只删记录不动文件；**例外**：文件在绑定文件夹内且记录为 file 型，删除时可选「连同文件删除」 |
| 图片格式白名单 | jpg/jpeg/png/webp/gif/avif/bmp |
| 缩略图 | 懒生成（首次浏览时降采样进 covers 缓存，复用画匣封面基建），网格不直接加载原图 |
| 评分/收藏的范围 | 评分 0–10 与画集同刻度；收藏（红心）为图级标记，另提供跨区「我的收藏」虚拟视图（V2） |
| 标签/备注 | V1 不做（画廊标签中心是画集粒度，单图标签另立项） |

## 三、数据模型（schema v10 草案）

```sql
CREATE TABLE image_collections (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,              -- 区名（= 默认文件夹名）
  folder TEXT NOT NULL UNIQUE,     -- 绑定的磁盘文件夹（绝对路径）
  created_at INTEGER NOT NULL
);
CREATE TABLE image_records (
  id INTEGER PRIMARY KEY,
  collection_id INTEGER NOT NULL REFERENCES image_collections(id) ON DELETE CASCADE,
  kind TEXT NOT NULL,              -- 'file' | 'archive_page'
  path TEXT,                       -- kind=file：图片绝对路径
  archive_id INTEGER,              -- kind=archive_page：源画集
  page_index INTEGER,              -- kind=archive_page：源页号
  rating INTEGER NOT NULL DEFAULT 0,
  favorite INTEGER NOT NULL DEFAULT 0,
  file_size INTEGER,
  width INTEGER, height INTEGER,   -- 元数据（扫描/收集时顺手取）
  missing INTEGER NOT NULL DEFAULT 0,
  added_at INTEGER NOT NULL
);
CREATE UNIQUE INDEX idx_image_records_unique ON image_records(
  collection_id, kind, COALESCE(path, ''), COALESCE(archive_id, -1), COALESCE(page_index, -1)
);
```

## 四、交互设计

1. **侧栏新增「散图」区**：区列表（文件夹图标 + 名字 + 张数）→ 点击进该区网格。
2. **区管理**：新建区（命名 = 自动建文件夹）、绑定已有文件夹、打开文件夹（资源管理器）、
   重新扫描、删除区（只删记录不删文件夹，二次确认）。
3. **网格视图**：懒加载缩略图 + 评分星 + 红心收藏 + 缺失角标；点击进单图查看器。
4. **单图查看器**：左右切换（区内顺序）/ 缩放 / 评分 / 红心 / 移除记录 / 「显示源」
   （archive_page 型跳转画廊对应包对应页）。
5. **画廊收集入口**：阅读器页内右键菜单 + 顶部按钮「收藏到散图」→ 区选择弹层
   （默认上次用的区）→ 动作二选一：**收藏（指向源页）** / **提取到文件夹**。
6. **导入**：区详情「打开文件夹」+「重新扫描」；扫描增量登记新文件，检测缺失。

## 五、里程碑

- **M1 数据层**：schema v10 迁移、区 CRUD、文件夹扫描（增量/缺失检测）、评分/收藏 API。
- **M2 浏览骨架**：侧栏散图区 + 区管理 + 网格（懒加载缩略图）。
- **M3 单图查看器**：切换/缩放/评分/收藏/移除/显示源。
- **M4 画廊联动**：阅读器收藏入口（指向源页/提取另存双模式）。
- **M5 打磨**：跨区「我的收藏」视图、拖拽导入、galleryctl `images` 命令。
